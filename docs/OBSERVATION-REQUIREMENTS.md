# 观察、监控与交付：本会话需求回顾

整理日期：2026-10-28。依据是本会话中用户的原始消息，包括用户转述的旧版本反馈，以及随后对这些反馈和助手方案的纠正。转述的 AI 建议不等于用户要求；助手实现的技术方案也不自动成为产品需求。本文保存需求依据与决策边界，待办仍统一维护在 [ROADMAP.md](ROADMAP.md)。

## 目标与问题判断

目标是让模型在 Minecraft 中获得足以决策的信息、持续接收行动反馈，并能用程序处理明确的监控条件。用户认可行动／反馈循环，但 Minecraft 的 unknown unknown 很严重：模型可能根本没想到要观察周围有哪些怪、目的地附近有哪些怪、自己与目的地及怪物之间是否连通。

用户不要求平台替模型选择战斗、撤退或冒险策略。开放与保守都可以是取舍；不能接受的是，开放建立在模型根本不知道需要检查什么之上。另一方面，用户明确提出“我们要求目标模型没有流体智力也能玩”，同时指出“目前已经有可以自己玩明白的 ai”。因此，既不能把失败全归结于模型能力，也不能假定靠少量提示词和范例就能补齐游戏理解。

最重要的证据判断纠正是：面对那次选定单怪战斗、没有取得周边怪物情况的轨迹，用户认为可以相当高程度判断模型当时就是不知道。不能把它弱化成“不能代表掌握现场”，再跳到“信息已经取得，只是没有形成场景”。工具内存在数据、程序读取了数据、模型实际看到了数据，是不同环节。至于模型为什么没有主动获取，仍不能单凭这段轨迹确定其心理原因。

## 必须同时保留的取舍

**默认信息与按需查询。** 用户接受较多默认态势信息，但旧方案已有内容冗余和 token 优化，也有显著成本。纯按需读取要求模型预先想到问题，无法单独覆盖 unknown unknown；恢复全量注入也不能自动保证模型利用信息。默认交付哪些内容、何时交付、重复多少，目前没有定案。

**模型阅读与程序监控。** 用户设想让模型写容易调用的条件监控，但同时指出这与“让模型看到更多信息、建立完整认知”存在张力。关系指标可以作为二级整理信息供模型理解，也可能逐步固化为我们替模型写游戏 AI。身体状态等明确量很适合程序处理，不必每次都让模型过目；这不意味着模型已经具备了选择全部必要监控维度的能力。

**提示词与交付保证。** 用户没有全面否定通过提示词教模型；其问题是这是否真能让原本不会的模型学会，以及收益是否值得。要求行动前观察是行为指令，保证信息进入某个模型请求是交付能力，两者须分别陈述。输出可被过滤、模型可不执行指令，不能靠更换接口名称消除。

**抽象层与功能设计。** 用户明确要求兼容免安装和有 hook，并指出抽象层本身也是功能设计。当前采用的边界是：事实计算可复用，读取／摘要不隐式消费，调用方负责提交读取进度；未来 hook 的交付回执不借用 CLI 游标。这是本轮实现选择，不代表已经决定默认观察产品形态，也不是要求建设通用事件框架。

## 已确认的实施约束

- 免安装的 shell／文件／普通 harness 交互是主要路径。安装式 plugin/hook 只记路线图，本轮不实现。
- 先稳定、打检查点，再重构底层；不急于增加动作关注、自动查询流水线、综合安全评分或更多观察功能。
- 观察事实、显示摘要和监控条件应能复用；不能让显示限额无意改变检测范围，不能把未知加工成确认没有。
- 检测到异常但仅写 stdout，不算完成唤醒链。测试要区分记录、等待返回、模型再次获得执行机会与模型实际改变策略。
- skill 内文案精炼、解释清楚、减少重复；不把被误读的范例加固成固定流程。
- 用户额度紧张，明确要求先不用 Sol。大面积代码／原始轨迹读取可交 Luna，长材料分段摘要以降低压缩损失；根代理保留整体理解与取舍。用户要求粗略比较合作前后根代理工作量，不为此查调用记录。

## 尚未决定的方向

1. 默认交付的信息子集、触发条件与预算。旧 inbox 是可复用的经验与内容基础，不能当作尚不存在的能力重新设计。
2. skill 中增加用途说明、少量完整范例或行为指令的程度。可作为方案，但效果未知，不应冒充交付保证。
3. 条件监控对外的最小接口，以及哪些指标只是事实整理、哪些已经隐含游戏策略。用户的一句话代码设想尚未落成接口需求。
4. hook 的具体 harness、安装／重载方式、注入边界和交付确认。保留免安装路径，不在本轮落地。

助手此前提出“下一步比较旧 inbox 与失败片段，决定默认交付子集”，这是后续研究建议；用户当前明确要求的是回顾原始消息、形成需求报告并与现有改动一起提 PR，并未据此批准恢复注入或扩展功能。继续推进时，应从上述未决取舍中选择有证据支持的一项，而不是把本轮实现反推成用户一直要求的完整方案。
