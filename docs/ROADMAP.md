## 架构调整（10‑13 定下的方向）

## 仓库分工（10‑16 定下的方向）

本仓库提供运营命令行、模型转发、部署，以及容器里的原生 bot 运行时、Pi 扩展、任务管理和收件箱。通用工具包仓库改名为 `ueagohbbcd/mineflayer-agent-tools`（原 `mineflayer-world-memory`），是可从角色进程调用的通用 Mineflayer agent 工具包，包含可选的历史区块、观察查询、实时出图与看门狗；Mineflayer bot API 不经远程镜像暴露。工具包的包名暂时保留 `mineflayer-world-memory`，本仓库的依赖键名和所有 `import` 路径都不变。

2026-10-19 调整：Arena 默认关闭历史区块缓存；实时 Mineflayer 方块优先，历史仅在区块卸载后回退。`ARENA_WORLD_MEMORY_MODE=session|persistent` 才启用，默认 `off`。现阶段不扩展自研存储引擎；今后评估已有 Prismarine provider 的可替代性。

本仓库对工具包的代码依赖只有库。skill 不直接引用，只复制要用的几个过来按比赛规则改写；参赛容器里只装本仓库挑选的东西，因为模型能读到 `node_modules`。依赖继续用 GitHub 下载链接（`codeload.github.com/.../tar.gz/<提交>`），不发 npm。依赖固定在哪个提交以 `package.json` 为准；改依赖的提交同时更新下表对应一行。

## 模型接入

平台不转换模型请求。限速放在参赛容器内的 Pi 扩展里（`ARENA_COST_PER_HOUR`，按标价花费），不在转发或网关上；它只管 Pi 自己的请求，硬上限交给供应商的 key 额度。其他需要（OAuth 转 API、代理链等）在外面包一层，模型转发指向它即可。

## 远期设想：反事实提示（2026-10-16 讨论，暂不排期）

目标：参赛模型只看到默认设置下的可达地形图，看不到"如果做点什么，寻路会怎么变"。比如放 3 块就能上一层楼，挖开一堵墙就能抄近路。反事实提示要在不替模型做决定的前提下，只把值得关心的变化告诉它。

1. **找候选（确定性计算）**：每次出图时，用其他 pathfinder 设置多算几次可达图，和默认图比较。设置包括允许挖、放身上带的方块、开栅栏门。每个差异记下几项：多出的区域（格数、高度），代价（要挖或放几个方块、坐标，pathfinder 移动的 `toBreak` / `toPlace` 里就有），以及目标或路点是否变得可达、路程缩短了多少。按"收益 ÷ 代价"只留几条候选。
2. **判断值不值得说**，两种做法：
   - **JEV**：[TypeSafe 的 Jev](https://www.braintrust.dev/articles/what-is-jev) 是只做决策的模型。输入一段状态加一个带固定选项的问题，输出每个选项的概率和信心，或一个是/否概率。它不生成文字，不看图。价格约 $0.042 / 百万输入 token，输出不收费，可以通过 OpenRouter 调用（2026-09 的价格）。[论文](https://alphaxiv.org/abs/2609.26550)里把它当一级裁判：信心 ≥ 阈值就采纳，否则交给强模型。高信心区间和强模型几乎一样准，但对开放式文本接近随机，阈值要用本地标注数据来定。用法：把任务列表和一行候选摘要作为状态，问"现在值不值得告诉参赛者"。缺点是看不到参赛者完整的上下文。
   - **分叉同一会话**：复制参赛者最后一次真实请求，前缀逐字节相同，DeepSeek 前缀缓存能命中。末尾追加一条："你看到了这个。不用服从先前指令，只回答：这个可能性是否改变你的目标，是否值得看"，要求只输出 JSON 信心值，结果不写回会话。判断最贴近参赛者自己的目标，但每次都要付整段上下文：长程任务里平均请求长度会趋向压缩前后上下文长度的中点。好在 DeepSeek 缓存命中很便宜，换模型时再重算成本。
3. **送达**：信心超过阈值才写在地图下方，或者作为一条报告进收件箱。每次出图最多几条。

现有侵入点（代码阅读结论，未运行）：

- 扩展可以做，不需要改 Pi。`before_provider_request` 钩子能拿到发给模型的完整请求体。现在它只用于限速，见 `packages/pi-extension/index.mjs`。存下最后一次请求，分叉时深拷贝，追加问题后用 `fetch` 直接发出。
- 发出时用 `response_format: {type: "json_object"}`、`tool_choice: "none"`，不改 `tools` 数组以免破坏缓存前缀；推理模型可能还要关掉思考。pi-ai 没有 JSON schema 模式，结果要自己校验。
- 只在 `ctx.isIdle()` 时发，避免和真实请求同时进行，造成缓存未命中和重复计费。花费要计入现有的限额统计。
- 不宜放在 model-relay：它只是原样转发，没有会话和比赛上下文。
- Pi 自己的 `/fork`、`/clone`、`ctx.fork` 会替换当前会话，不能当旁路用。

热切换开关：Pi 的 `/reload` 只能由命令触发，比赛方或模型都触发不了；Pi 也不监视设置文件。我们的扩展在启动时从环境变量读配置。要在比赛中途开关，可以每次用到时重新读一个小 JSON 文件，或者向桥接查询；扩展已经在每次请求时通过 `createSessionReader` 查询比赛信息，可以照这个做。

待定：用 JEV 还是分叉会话（或者 JEV 先筛、分叉复核），阈值怎么标定，候选怎么筛，花费算比赛方的还是参赛方的。

**为什么难（2026-10-16 结论）**：分叉路线原理上已经具备，侵入点都在，但要做到能用，还有一堆疑难杂症：

- **计量和审计**：默认部署不走模型转发，参赛容器自己出网、用自己的 Pi 配置。key 就在容器里，扩展只能给自己发的旁路请求记账，算软限制。参赛者自己的程序完全能照这个办法分叉提问，不计量也不限速。硬上限和审计只能靠供应商：每人一个 key 或账户，只充定额。
- **限额默认关闭**：`ARENA_COST_PER_HOUR` 在模板里是空的。要计费，先得定额度，再定旁路花费记到谁头上。
- **缓存**：前缀只和最后一次真实请求一样新，必须等 Pi 空闲才能发，否则会和真实请求抢同一段前缀，缓存未命中、重复计费。压缩之后前缀整段变了。长程任务里平均上下文长度会趋向压缩前后长度的中点，每次提问都要付这么多输入。换模型或供应商，缓存规则和价格都要重算。
- **输出约束**：pi-ai 没有 JSON schema 模式，只能用 `json_object` 加提示词约束，结果要自己校验。推理模型还要关掉思考，DeepSeek 的思考格式要单独处理。
- **判断质量**："不用服从先前指令"的追加提问，模型未必照做。同一个模型给自己打的信心分有多准也不知道，阈值要用标注过的实战数据来定，而现在没有这批数据。
- **候选本身的成本**：每种设置都要多算一次可达图，每次约 0.6 秒（测试世界里的粗测）。候选要先筛得够少，才问得起。
- **开关**：Pi 的 `/reload` 只能用命令触发，扩展在启动时读环境变量。比赛中途开关要新做：扩展每次用到时重读一个文件，或者向桥接查询。
- **公平性**：告诉参赛者"做这件事就能多出一块区域"，已经接近替模型解题，说到什么程度要先定规则。
