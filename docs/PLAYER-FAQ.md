# 控制程序的几个短提醒

从任务、现成能力和当前观察开始行动。需要某个方法时查对应官方 API；这里保留实际控制流程中容易漏掉的细节。

### 刚装备了方块或镐，为什么后来拿着剑或西瓜？

后台进食和守卫程序会改同一角色的主手。2026-10-11 合作试验中，Light 搭柱到
Y=46 时被自动进食换成西瓜，放置报 `Server refused to place melon_slice`；
Medium 曾拿着守卫换上的剑放墙；Heavy 进食后继续徒手挖石，速度很慢且没得到圆石。
Light 暂停守卫后完成搭柱，Medium 加入施工锁，Heavy 在每个采掘段重新装备镐。

让使用主手的实际程序协调交接，在恢复施工或采掘时装备该段需要的物品。
[导航进食](../examples/navigate-with-autoeat.mjs) 展示暂停与恢复，
[施工进食](../examples/build-with-autoeat.mjs) 展示同一程序内的手部串行化。

### 我已经给 Pathfinder 关了挖掘，为什么 PvP 仍会挖？

PvP 有独立的 `bot.pvp.movements`，`attack(entity)` 会将它交给 Pathfinder。
要保留战斗途中的地形，直接设置 `bot.pvp.movements.canDig = false`。
[战斗薄示例](../examples/observe-pvp.mjs) 展示这个接点。

### `pathfinder.stop()` 返回了，可以立刻换手吃饭吗？

它请求走到下一个路径节点再停，返回值不是完成 Promise。等待原 `goto`
收到 `PathStopped` 后，再检查落地及挖掘／放置完成，才借用手部控制。
`path_stop` 本身也不保证已经落地。[导航进食示例](../examples/navigate-with-autoeat.mjs)
保留原目标，进食后重新 `goto`；取消则清目标并释放控制，结束这个恢复流程。

### 自动战斗结束后，下一轮模型能看到什么？

标准 PvP 适配器默认通过普通 Inbox 合并报告执行经过：起止、目标、攻击尝试、
追击距离、血量与收到的附近潜在敌对实体增减。你的选择算法可另外提供候选和理由。
这样下一轮可以按实际过程调整自己的策略。攻击尝试不等于命中，实体离开观察范围
也没有证明被击杀；摘要保留这些证据的实际含义。

### 原生动作完成和观察更新是一回事吗？

`consume()` 等待原生完成并刷新库存。`wake()` 返回表示已发送请求，
`wake` 事件或 `isSleeping === false` 表示观察到醒来。按需要使用对应接口即可。

### 提前返回后，原程序还在吗？

`running` 是返回当时的状态；程序可能在模型思考期间完成。对同一 `taskId`
直接等待或取消，处理返回的 `completed`／`delivered` 即可，无须先单独查一次。
若要启动替代程序，先等旧任务确实终止；`task_wait` 仍可能因紧急事件或超时返回 `running`。
游戏会一直继续；需要后台保护时让自己的程序保持运行，到达后退出的示例不继续值守。
