# 模型上下文：来源与时机

本文写给要修改 Pi 扩展、默认模块或自动报告内容的开发者。它说明参赛模型在什么时候看到什么。参赛模型自己读到的说明在 [participant/agents.d/10-arena.md](../participant/agents.d/10-arena.md)；术语见 [README](../README.md)。

## 原则

游戏里发生的事不会自己进入模型的上下文。角色、程序和默认模块由工具包的 `mf` 运行，报告进 `mf` 的收件箱，只有模型运行 `mf inbox`（或 `mf run --inbox S`）时才取出。Pi 扩展只管“命令”这一层：命令什么时候结束、结束了告诉模型，再加上可信侧的平台消息。

所以程序需要模型做决定时，应该**结束**并在返回值里说明原因：结束会送到模型那里，报告只会在收件箱里等。`requestJudgment` 发的是紧急报告：在 `mf inbox` 里排在前面，并让正在等待的 `mf run` 提前返回 `running`（程序继续跑，见下文）；没有 `mf run` 在等时，它只在收件箱里等。

## 请求边界

模型只在发出一次请求时读取上下文。两次请求之间，游戏和程序照常运行。本项目的 `bash`（带 `command` 启动任务，或带 `taskId` 接着等）在两种情况下返回：

- 命令结束：返回 `completed` 和输出。
- 等待时长用完（默认 30 秒，`wait_seconds` 或 `ARENA_TOOL_WAIT_SECONDS` 可改）：返回 `running` 和 `taskId`，**命令继续运行**。之后每次返回 `running` 只带上次返回之后的新输出。完整输出在任务目录的 `stdout.log`／`stderr.log`。

`mf run` 是一条普通命令：它一直等到程序结束，边运行边打印输出。`bash` 的任务被停掉时 `mf run` 这个客户端退出，程序本身继续在角色上跑；停程序要用 `mf cancel`。

Pi 在下面这些时刻发出请求：

| 请求边界                     | 例子                                                          |
| ---------------------------- | ------------------------------------------------------------- |
| 一条 prompt 开始一轮对话     | 启动器发出的开局提示；请求恢复发出的续写提示                  |
| 一批工具调用全部返回         | 同一条模型回复里的所有工具调用都返回后                        |
| 一轮结束时扩展要求继续       | `turn_end` 返回 `continue: true`                              |
| 扩展发出一条触发新一轮的消息 | 空闲时命令结束（`arena-tasks`）、空闲提醒、新通知（平台消息） |

## 什么时候送达什么

| 时机               | 内容                                                                                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本身就是边界       | `bash` 返回；开局提示（会话简报、玩法说明、会话文件路径）                                                                                             |
| 随下一次边界附带   | 没有等待者时结束的命令（`Finished tasks`，附在工具结果末尾或 `turn_end` 的历史记录里）；平台消息里变化了的 `session`／`public`／`notice`／`modelRate` |
| 唤醒空闲的模型     | 空闲时结束的命令（包括因紧急报告提前返回的 `mf run`）；`public.notice` 变化；会话进行中且模型启动的命令都已结束 5 秒（`ARENA_IDLE_REMINDER_MS`）后的空闲提醒                               |
| 只在模型查询时读取 | `mf inbox`：默认观察器、聊天、看门狗和程序的报告，以及死亡、断线、维度变化、会话状态变化等“停止”（stop）；`mf snapshot`；`mf status`；任务日志；截图          |

“停止”（stop）就是数据里带 `stop: "原因"` 的报告，supervisor 自己发死亡、断线、维度变化、会话状态变化、进程崩溃或无响应这几种，程序和规则也可以发。它会中断角色当前的程序，并让该角色之后的 `mf run` 返回 `not_started`，直到模型用 `mf inbox` 读到它（以 `! stop:` 行列在最前，永不丢弃、不过期）。这保证模型不会在没看到死亡的情况下继续给角色下命令。

紧急报告（停止以外）不拦截，只让正在等待的 `mf run` 立即返回 `running`，程序继续在后台跑：前台等待时模型马上看到；被 Pi 转到后台的 `mf run` 因此结束，等于唤醒模型。来源：危险血量或短时间大量掉血、同一处反复死亡、程序的 `requestJudgment`、`ARENA_CHAT_WAKE` 匹配的聊天。

上下文被压缩后，扩展在下一次请求前补一条 `arena-after-compaction`：仍在运行的命令和一次 `mf inbox --full` 的输出（observer 重发的完整状态加上所有未读报告；observer 之后的报告是相对它的变化）。模型也可以随时自己运行 `mf inbox --full`。

## 平台消息

平台消息不进收件箱。`turn_end` 时扩展通过只读 `session` 接口读取会话状态（缓存 2 秒，超时 300 ms），`kind`、`sessionId`、`state` 或 `winner` 有变化时组成带 `session` 段的平台消息，用 `triggerTurn: false` 交给 Pi。不报已用时间和剩余时间：时限由服务器上的规则执行，模型不知道。

`public` 段：开局提示里的 `briefing.public` 是基线，之后它一变，下一条平台消息就带 `public`（JSON 超过 4096 字节时只报大小和 `public.json` 的路径）。`public.notice` 变化时另带 `notice` 段（超过 2000 字符截断）。Pi 空闲时扩展每 `ARENA_NOTICE_POLL_MS`（2000 ms）读一次会话，通知一变就用 `triggerTurn: true` 发一条平台消息开启新一轮。

所有来自可信侧的消息都由 `index.mjs` 的 `deliverPlatform` 发出，以 `Arena platform message` 开头。

## 默认收集与默认交付

| 能力         | 默认收集                   | 交给模型                                                |
| ------------ | -------------------------- | ------------------------------------------------------- |
| 默认观察器   | 是，每秒采样               | 进 `mf inbox`，每个角色只留最新一份状态报告             |
| 沿途方块报告 | 是，每秒采样               | 进 `mf inbox`；有上次读过的报告里没有的方块种类或范围时立即可读，否则攒满 30 秒 |
| 默认聊天转发 | 是                         | 进 `mf inbox`（未读聊天合成一条 `game.chat`）；`ARENA_CHAT_WAKE` 让匹配的聊天变紧急：排在前面，并让正在等待的 `mf run` 提前返回 |
| 看门狗       | 是                         | 持续数分钟的异常进 `mf inbox`                           |
| 图像         | 否，运行截图脚本时才生成   | 模型用 `read` 读截图脚本写出的 PNG                      |
| 区块记忆     | 运营方打开时，在角色进程中 | 不交付，模块查询时才读                                  |
| 平台消息     | 是                         | 只发变化部分，随下一次请求附带；通知会唤醒              |

默认收集只花机器资源；默认交付占用模型的上下文。新增或修改一项默认报告时，回答：汇总会不会漏掉影响行动的短时信息；来回走、原地不动时会不会反复占上下文；需要模型马上处理的事，是否应该由程序结束来表达，而不是一份报告。

## 已退役的方案

“每次请求都附上最新观察”的请求尾部方案和收件箱自动注入都已删除；紧急报告现在只让正在等待的 `mf run` 提前返回。前者的机制和放弃理由见 [实验记录](history/EXPERIMENTS.md)。
