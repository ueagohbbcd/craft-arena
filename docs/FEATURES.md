# 主要特性与交付状态

测试场为通用 coding AI 提供公开一致的游戏角色、工具、资料与有限资源。AI 自主选择策略和执行方式，比赛结果用于比较效果。

开始操作可先读 [玩家入门](PLAYER.md)。下列“已实现”指源码已有对应能力；本地验证与实战验收范围见 [验证记录](VALIDATION.md)。部署配置由运营者完成，“可自组织”由参赛代码安排。

框架提供比赛制度、可信角色接口、Agent 程序生命周期／Inbox 与统一模型资源约束；Pi 是当前 Agent 的适配入口。态势感知、世界视觉、区块记忆属于**并列的预装工具箱能力**，并非框架的三个额外层次。Skill、源码和示例提供调用与二次编程入口。三者分别有默认监听、地图配置的开局图像、可信侧默认收集区块等行为；默认开启不改变它们作为工具箱的性质。[总体边界](../README.md#框架预装工具箱与-skill) · [后续解耦工作](PERCEPTION-TODO.md)。

## 比赛与角色

1. **PvP 竞速比赛｜已实现，需配置地图。** 围绕 Race of Wool 一类目标组织准备、开局、比赛和结束。运营者固定地图、队伍、时限与获胜规则。实战适配器按纪念碑当前方块状态计分，选图须与此判定方式一致。[比赛宿主](../packages/arena/README.md)

2. **每个参赛单位一个容器、一个角色｜部署模板已提供。** Pi 和参赛代码在容器内运行，真实 Mineflayer bot 在可信后端运行。模板给出网络、CPU、内存与进程限制；目标 Docker 主机上的隔离效果须验收。[运营部署](../infra/README.md)

3. **自由编程与执行方式｜已实现。** AI 可逐步操作，也可写普通 Node 函数、脚本、事件监听器和 Promise，自主组织采集、施工、战斗与角色控制。[参赛指南](../examples/SKILL.md)

## 观察与游戏执行

4. **Mineflayer 风格状态与动作、选定插件｜已实现，兼容范围有界。** 同步本地镜像支持查询与寻路；公开语义动作由可信后端校验执行。提供固定版本 Pathfinder/PvP 适配、自定义 Goal 与 Movements；动态地形和实战行为须按选图验证。[SDK 与兼容清单](../packages/bot-sdk/README.md)

5. **预装态势感知｜已实现，默认启用。** 这是可供参赛代码复用的观察／监听工具箱，当前由 Pi 会话启动只读观察：开局交付基础状态，后续顶层工具结果与新一轮入口交付变化部分，保留普通历史。内容包括自身、背包数量、装备、当前窗口、实体雷达、局部环境和受管程序状态（`taskId`）。沿途方块累计摘要与附近牌文字变化分别进入普通收件箱，另有受伤、关键物品损失／耗尽、羊毛获得／失去、死亡／出生和连接变化事件。控制程序可直接复用同源观察函数。[观察架构与覆盖范围](OBSERVATION.md)

6. **按需观察、视觉库与区块记忆｜已实现。** `observe` 只返回状态 JSON，可直接阅读，按需用 `fullItems`、`fullEntities`、`fullLocal` 等展开细节。开局图像由启动流程按地图配置作为用户消息交付，与会话观察各自独立。需要新视角时运行普通脚本 [observe-and-render.mjs](../examples/screenshot.mjs)（Prismarine 观看器 + 本地 Chromium 截图，可传显式边界）。共享区块记忆默认在可信 Bridge 中记录角色实际接收的完整区块，脚本按需查询已卸载的历史；历史不保证当前仍然有效。这三项预装能力的使用说明位于 Skill／源码／文档中，并不要求模型另造框架。[观察用法](OBSERVATION.md#一次观察与按需图像) · [区块记忆](BLOCK-MEMORY.md) · [图像库](../packages/world-visual/README.md)

7. **持续运行的普通程序｜已实现。** 程序可在模型思考、排队或暂时结束回答后继续运行。工具等待和进程寿命分开；AI 通过 taskId 等待结果或明确取消，比赛结束时运行时清理进程。[Pi 运行集成](../packages/pi-extension/README.md)

## 模型判断与资源

8. **普通历史与可替换程序状态｜已实现。** 工具结果、查询、观察变化和已交付收件箱事件保留历史。程序可用 `post` 记录事件、`upsert` 合并待交付报告，或用 `publishCurrent` 维护有时效的当前值，供后续 `programStatus` 观察读取。紧急事件释放受管工具等待并保留进程，常驻模式可唤起空闲中的同一会话；程序报告携带任务关联。[历史与状态](OBSERVATION.md#历史与本次请求状态) · [收件箱](../packages/inbox/README.md)

9. **直接工具与普通程序｜默认启用。** 文件工具处理代码，`bash` 运行 Node 程序，`observe` 直接返回状态 JSON；`task_wait`／`task_cancel` 管理同一程序的等待与取消。codemode 默认关闭，显式 CLI 工具选择仍保留。[用法示例](../examples/SKILL.md)

10. **按 API 标价折算成本的窗口限速与反馈｜已实现，需配置模型价格与速率。** 网关统一计量个人／队伍的参考成本，覆盖主 agent、子代理和摘要请求，按时间窗口容量排队。模型看到窗口内各计费项成本占比、速率超支比例、实际排队延迟和计量质量；运营者查看累计金额并通过可信 host 决定何时结束比赛。账本当前为单进程内存状态。[预算网关](../packages/budget-gateway/README.md)

## 协作、引导与结果

11. **队内 Git、游戏聊天与子代理｜部署接线与参赛自组织。** Git 共享卷已接入模板，运营者初始化队内仓库；聊天经游戏桥发送，其可见范围由服务器／地图配置。子代理可由参赛代码自行启动和调度，使用本参赛单位的网关身份与预算；平台提供运行和计量条件，调度与并发角色协调由参赛代码实现。[部署说明](../infra/README.md)

12. **一次开局任务与持续比赛上下文｜已实现。** 常驻 Pi 等待可信开局状态，提交一次公开任务说明。后续工具结果、观察变化、程序事件、预算与墙钟反馈进入同一会话，终局状态触发清理。[启动与生命周期](../packages/pi-extension/README.md)

13. **短说明与可运行教学材料｜已提供。** 启动入口加载行为指南与编程技能，说明系统入口、适配差异、观察交付和程序等待。导航、容器操作与开局图像有真实使用记录；进食／自卫示例展示如何记录短动作经过和恢复，运行与策略由参赛代码选择。加载标准 PvP 适配器时自动启用战斗过程报告。[短说明](../AGENTS.md) · [编程指南](../examples/SKILL.md) · [验证范围](VALIDATION.md)

14. **可信判定与结果记录｜已实现，实战对局待验收。** 比赛宿主接收可信目标信息，处理当前进度、超时和异常，保存结果与版本标识。真实地图重置、同步开局、目标观察和终止清理须完成实战冒烟验收。[比赛宿主](../packages/arena/README.md) · [验证记录](VALIDATION.md)
