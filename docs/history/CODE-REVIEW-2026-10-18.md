# 代码与架构审查（2026-10-18）

审查基线：`8a16806fffe99900b5224338486e89373949384e`。范围包括包结构、桥与 SDK、事件消费者、原生运行器、部署边界和自动化测试。未进行真实 Minecraft 性能压测；本次不能据此声称运行时性能提升。

## 判断

项目的主要复杂度来自同时支持原生与桥接两种运行时，以及 SDK 对 Mineflayer 同步状态的兼容。直接删除桥或通用调用会影响现有部署；仅把大文件切开也不会显著减少总代码量。值得先消除的是协议的多份实现和测试导入副作用，再处理原生运行器的生命周期。

按 `packages/**/*.mjs` 的物理行数计，生产代码从 15,992 行变为 15,983 行，净减 9 行。桥入口从 1,571 行减为 1,457 行，其中主要是职责迁移，不能把迁移量算成总代码删减。新增测试不计入生产代码量。

## 尚存的结构性风险

- **原生运行器取消不是强制终止。** `packages/mf-bridge/runner.mjs` 的 `cancel()` 仅触发 AbortSignal，停止移动和清理发生在模块结束后的 `finally`。不响应 signal 的异步模块可能持续运行；同步死循环则阻塞整个 bot 进程。当前取消测试覆盖配合 signal 的模块，不能证明强制终止有效。
- **运行器资源归属存在边界。** 同一文件的 `runBot()` 在注册监听后返回原始 target，链式 `.on().on()` 的后续调用可绕过监听记录；全局计时器包装记录运行期句柄，但未覆盖所有计时器入口。修复需要围绕模块、插件、bot 三种生命周期建立可执行约定，不能只靠移动函数。
- **原生与桥接的部署事实仍需统一。** `docs/TARGET-ARCHITECTURE.md` 已说明 native 是默认，README 的旧流程及若干术语仍沿用 bridge。当前 README 已标明适用范围；后续文档整理统一记在 ROADMAP。
- **SDK 和观察层仍有较大的职责集合。** 基线 SDK 入口 1,264 行，观察快照 901 行、可达性模块 877 行。窗口镜像、事件恢复、地形计算各有语义边界；拆分应围绕这些职责并保留现有回归测试，而不是引入通用框架缩短表面行数。

待办只维护在 [ROADMAP](../ROADMAP.md#代码整理简化审查中暂缓的项)，本页保存审查证据。
